# 할 일 관리 앱 — 클로드 코드 단계별 프롬프트

작성일: 2026-10-01 (KST)
대상 명세: [2026-10-01-할일관리앱-design.md](../specs/2026-10-01-할일관리앱-design.md)

PRD 를 클로드 코드에 그대로 넣을 수 있는 **5개 프롬프트** 로 나눈 것이다.
각 프롬프트는 자기 완결적이다 — 앞 단계를 기억하지 못하는 세션에 붙여 넣어도
무엇을 만들고 어떻게 확인하는지 알 수 있다.

## 쓰는 법

1. 아래 프롬프트를 **순서대로 하나씩** 붙여 넣는다. 한 번에 여러 개를 주지 않는다
2. 각 단계 끝의 **완료 기준** 을 직접 확인한 뒤 다음으로 넘어간다
3. 단계마다 커밋한다. 틀어지면 그 단계만 되돌린다

## 모든 단계에 걸리는 규칙

프롬프트마다 반복해 넣어 두었지만, 한 번에 보면 이렇다.

- `index.html` **단일 파일**. HTML·CSS·JS 를 한 파일에 담는다
- 외부 의존성 **0** — 라이브러리·CDN·웹폰트·아이콘 금지. 네트워크 요청 0건
- **한글 식별자·한글 주석**
- ES2020, 빌드 과정 없음. 전체 600줄 안쪽을 목표로 한다
- 사용자 입력은 **`textContent` 로만** 넣는다. `innerHTML` 에 사용자 문자열 금지
- `localStorage` 접근은 **전부 `try`/`catch`**
- 시각은 저장 UTC ISO 8601, 표시 KST
- 카테고리는 **업무 / 개인 / 공부 고정 3개**, 제목은 1~200자

## 1단계 — 순수 함수와 자가검증 하네스

```
D:\DSMP\study02_todolist 에서 작업한다.
docs/superpowers/specs/2026-10-01-할일관리앱-design.md 의 5절(데이터 모델),
6절 F1~F7, 8.2(1계층), 10절(검증 전략)을 먼저 읽어라.

index.html 을 새로 만들고, 그 안에 자가검증 하네스와 순수 함수 계층만 넣어라.
화면(HTML·CSS)과 저장(localStorage)은 이 단계에서 건드리지 않는다.

[만들 것 — 자가검증 하네스]
- location.search 에 "검증" 이 있을 때만 실행된다. 평소에는 아무 흔적도 없다
- 확인(이름, 실제, 기대) 로 단언하고, JSON.stringify 로 비교한다
- 끝에 "통과 N / 실패 M" 과 실패 항목의 기대값·실제값을 화면에 표로 띄운다
- 하네스는 DOM 과 localStorage 를 건드리지 않는다

[만들 것 — 1계층 순수 함수, 이 이름 그대로]
  빈상태() → 상태
  제목다듬기(값) → 문자열 | null        (trim, 200자 초과는 자름, 빈 문자열은 null)
  할일추가(상태, 제목, 카테고리) → 새 상태
  할일수정(상태, 번호, 제목, 카테고리) → 새 상태
  할일삭제(상태, 번호) → 새 상태
  완료뒤집기(상태, 번호) → 새 상태
  완료항목비우기(상태, 카테고리) → 새 상태   (해당 카테고리의 완료 항목만)
  목록걸러내기(할일목록, 카테고리) → 사본
  목록정렬(할일목록) → 사본               (미완료 먼저, 각 묶음 안 번호 내림차순)
  진행률계산(목록) → {완료수, 전체수, 백분율}
  카테고리별개수(할일목록) → {전체, 업무, 개인, 공부}
  데이터검증(임의값) → {상태, 복구실패수, 고침수}

이 함수들은 DOM 도 localStorage 도 건드리지 않는다. 전부 새 객체를 돌려주고
인자를 변경하지 않는다.

[특히 주의]
- 진행률 백분율은 양 끝을 막는다. 전부 완료가 아니면 최대 99, 하나라도 완료면
  최소 1 이다. 199/200 은 반올림하면 100 이지만 99 로, 1/300 은 반올림하면 0
  이지만 1 로 나와야 한다. 명세 F6 의 코드를 그대로 쓴다
- 데이터검증은 명세 7.2 의 표 12행을 전부 처리한다. 살릴 수 있는 것만 살리고,
  정상 데이터는 아무것도 바꾸지 않아야 한다(이게 가장 중요한 검증 항목이다)

[검증 — 명세 10.3 의 항목을 전부 쓴다]
최소 45개 이상. 진행률 경계 6개(0/0, 0/10, 10/10, 199/200, 1/300, 1/3),
데이터검증 12유형, 불변식 4개(번호 유일 / 모든 번호 < 다음번호 / 카테고리 고정
3개 / 제목 길이 1~200)를 반드시 포함한다.

[완료 기준]
저장소 뿌리에서 `python -m http.server 8000` 을 띄우고
http://localhost:8000/index.html?검증 을 열었을 때 "실패 0" 이 보인다.
file:// 로 열면 쿼리스트링이 날아갈 수 있으니 반드시 로컬 서버로 확인한다.

[하지 말 것]
화면 만들기, localStorage 쓰기, 이벤트 처리. 다음 단계의 일이다.
```

## 2단계 — 저장 계층과 데이터 보존

```
D:\DSMP\study02_todolist 에서 작업한다.
docs/superpowers/specs/2026-10-01-할일관리앱-design.md 의 5.1(저장 형식),
7.1 / 7.2 / 7.4, 8.2(2계층)를 먼저 읽어라.
index.html 에는 1단계의 자가검증과 순수 함수가 이미 들어 있다.

index.html 에 저장 계층을 추가하라. 화면은 아직 만들지 않는다.

[만들 것 — 2계층, 이 이름 그대로]
  저장가능여부확인() → 불
  저장하기(상태)
  불러오기() → 상태
  손상데이터보존(원본문자열) → 불

저장 키는 할일앱.데이터 하나다. 저장 형식은 { 스키마버전: 1, 다음번호, 할일목록 }
이고, 화면 상태(선택카테고리·편집중번호·저장가능·경고들)는 저장하지 않는다.

[반드시 지킬 것 — 이 앱의 실패 조건은 "데이터가 조용히 사라지는 것"이다]

1. localStorage 접근은 전부 try/catch 로 감싼다. 던지는 예외가 앱을 멈추게 하면
   안 된다
2. 시작할 때 쓰기 시험으로 가용성을 확인한다. 쓸 수 없으면(사생활 보호 모드 등)
   상태.경고들 에 "이 브라우저에서는 저장할 수 없습니다. 새로고침하면 작성한
   내용이 사라집니다." 를 넣는다. 앱은 메모리에서 계속 동작한다
3. 저장된 데이터를 읽을 때 JSON.parse 실패나 데이터검증의 복구실패수/고침수가
   0 이 아니면:
   a. 먼저 원본 문자열을 할일앱.손상된데이터.<UTC ISO 시각> 키에 그대로 보존한다
   b. 그 다음 경고를 넣는다. 몇 개를 복구하지 못했는지와 보존 키를 함께 알린다
   순서가 중요하다. 보존 없이 버리면 안 된다
4. 저장 중 QuotaExceededError 가 나면 "저장 공간이 꽉 찼습니다. 완료 항목을
   비워 주세요." 를 알린다. 메모리 상태는 유지한다

[검증]
자가검증은 1계층만 시험하므로 이 단계에서 늘릴 항목은 없다. 대신
?검증 이 여전히 "실패 0" 인지 확인해 1단계를 깨뜨리지 않았음을 보여라.

[완료 기준]
?검증 이 여전히 실패 0 이다. 브라우저 콘솔에 오류가 없다.

[하지 말 것]
화면 만들기, 이벤트 처리.
```

## 3단계 — 화면과 렌더

```
D:\DSMP\study02_todolist 에서 작업한다.
docs/superpowers/specs/2026-10-01-할일관리앱-design.md 의 9절(화면 설계),
8.2(3계층), 8.4(데이터 흐름), 8.5(성능), 7.5(포커스), 7.7(경계)을 먼저 읽어라.
index.html 에는 1~2단계의 순수 함수와 저장 계층이 들어 있다.

index.html 에 정적 골격·스타일·렌더 계층을 추가하라. 아직 클릭은 동작하지 않아도
된다 — 이 단계의 목표는 "상태를 주면 화면이 정확히 그려진다" 이다.

[정적 골격 — 자바스크립트가 채울 자리는 비워 둔다]
  경고 띠 자리 (처음엔 비어 있음)
  헤더 (앱 제목 + 진행률 막대·숫자)
  입력 줄 (제목 입력란 · 카테고리 선택 · 추가 버튼)
  카테고리 필터 버튼 4개
  목록 <ul> (비어 있음)
  바닥 (완료 항목 비우기 버튼)

[만들 것 — 3계층]
  렌더()
  ├ 경고띠그리기()  ├ 진행률그리기(보이는목록)  ├ 필터그리기()
  ├ 목록그리기(보이는목록)  ├ 바닥그리기(보이는목록)  └ 포커스복원()

[반드시 지킬 것]
- 렌더 안에서 상태를 바꾸지 않는다. 읽기만 한다
- 입력 줄은 다시 그리지 않는다. 그래야 카테고리 선택값과 타이핑 중인 글자가
  렌더에 휘말리지 않는다
- 목록은 DocumentFragment 에 조립해 한 번에 교체한다. 항목마다 DOM 에 붙이지
  않는다
- 사용자 문자열(제목)은 textContent 로만 넣는다. innerHTML 금지
- 각 항목에 data-번호 와 data-동작 을 붙인다(다음 단계의 이벤트 위임용)

[화면 규칙]
- 진행률은 헤더 안에 둔다. 레이블 앞에 현재 필터 이름을 붙인다:
  "전체 7 / 18 (39%)", 업무 필터면 "업무 7 / 12 (58%)"
- 완료 항목은 목록 아래로 내려 투명도를 낮추고 제목에 취소선. 완료 묶음 앞에
  "완료 N" 구분선
- 빈 상태: 전체면 "할 일이 없습니다", 카테고리 필터면 "업무 할 일이 없습니다",
  미완료만 0개면 "모두 끝냈습니다"
- 카테고리는 색 점 + 글자(배지). 색만으로 구분하지 않는다
- 색은 CSS 변수로 :root 에 모으고, prefers-color-scheme: dark 에서 재정의한다
- 360px 폭에서 가로 스크롤이 없다. 터치 대상 최소 44x44px
- 긴 제목은 overflow-wrap: anywhere 로 줄바꿈해 레이아웃을 깨지 않는다
- 체크박스는 실제 <input type="checkbox">, 버튼은 실제 <button>
- 진행률 막대에 role="progressbar" 와 aria-valuenow/valuemin/valuemax
- 필터 버튼에 aria-pressed, 아이콘 버튼(✎ ✕)에 aria-label
- 포커스 표시를 지우지 않는다(outline: none 금지)

[완료 기준]
?검증 이 여전히 실패 0 이다. 브라우저 콘솔에 오류가 없다.
개발자 도구 콘솔에서 상태에 할 일 몇 개를 직접 넣고 렌더() 를 부르면 목록·
진행률·필터 개수가 정확히 그려진다. 다크 모드와 360px 폭에서도 읽힌다.

[하지 말 것]
이벤트 처리. 다음 단계의 일이다.
```

## 4단계 — 사건 처리 (F1~F7)

```
D:\DSMP\study02_todolist 에서 작업한다.
docs/superpowers/specs/2026-10-01-할일관리앱-design.md 의 6절 F1~F8,
8.3(핵심 불변식), 7.5(포커스 복원)을 먼저 읽어라.
index.html 에는 1~3단계의 순수 함수·저장·렌더가 들어 있다.

index.html 에 사건 계층을 추가해 앱을 실제로 동작시켜라.

[가장 중요한 것 — 이 구조가 이 앱의 핵심이다]

  function 적용(새상태) {
    상태 = 새상태;   // 1. 교체
    저장하기(상태);  // 2. 저장
    렌더();          // 3. 그리기
  }

상태를 바꾸는 유일한 통로는 적용() 이다. 상태를 직접 대입하는 곳은 적용() 과
최초 초기화 두 곳뿐이다. 사건 핸들러는 순수 함수를 불러 새 상태를 얻고 적용()
에 넘기기만 한다. 이 규칙이 지켜지면 "저장은 했는데 화면이 안 바뀜" 과
"화면은 바뀌었는데 저장이 안 됨" 이 구조적으로 불가능해진다.

[만들 것]
- 목록에는 이벤트 리스너를 하나만 붙인다(이벤트 위임). 항목마다 붙이지 않는다.
  어느 항목인지는 data-번호, 무엇을 할지는 data-동작 으로 판별한다
- F1 추가: 제목 입력란에서 Enter 로 추가된다. 추가 후 입력란을 비우고 포커스를
  그대로 입력란에 남긴다(연속 입력이 끊기면 안 된다). 카테고리 선택값은
  마지막으로 고른 것을 유지한다. 빈 제목이나 공백만이면 추가하지 않고 안내만
  띄우며 포커스를 유지한다
- F3 삭제: 확인 없이 즉시. 편집 중이던 항목이면 편집 상태도 푼다
- F4 완료 체크: 체크박스로 뒤집는다. 항목 줄 전체를 클릭 영역으로 쓰지 않는다
  (체크박스와 제목 편집의 역할이 겹치면 오조작이 난다)
- F5 필터: 누르면 선택카테고리를 바꾼다. 필터는 저장하지 않는다
- F7 완료 항목 비우기: confirm() 으로 한 번 확인한 뒤, 현재 필터에 보이는 완료
  항목만 지운다. 업무 필터에서 눌렀는데 공부 할 일이 사라지면 안 된다.
  완료 항목이 0개면 버튼은 비활성
- F2 제자리 수정: 제목이나 ✎ 를 누르면 그 줄이 편집 상태가 된다(상태.편집중번호).
  제목 입력란과 카테고리 선택이 그 자리에 나타난다. Enter 로 확정, Escape 로
  취소한다. 한 번에 한 항목만 편집하고, 다른 항목 편집을 시작하면 앞의 것은
  확정된다. 제목을 비우고 확정하면 거부하고 편집 상태를 유지한다(항목이
  삭제되면 안 된다) — 이때 빠져나오는 길은 Escape 다
- 렌더 후 편집 중이던 입력란에 포커스와 커서 위치를 되돌린다. 이 복원 코드는
  렌더() 의 끝 한 군데에만 있어야 한다. 흩어지면 구조의 이점이 사라진다

[완료 기준 — 브라우저에서 직접 확인한다]
1. ?검증 이 여전히 실패 0
2. 제목을 치고 Enter 만으로 추가된다. 마우스를 쓰지 않는다
3. 추가·수정·삭제·체크·비우기 각각 후 새로고침해도 결과가 유지된다
4. 체크하면 완료 묶음으로 내려가고 진행률이 즉시 오른다
5. 필터를 바꾸면 목록과 진행률 레이블이 함께 바뀐다
6. 편집 중 다시 그려져도 포커스와 커서가 유지된다
7. 제목에 <img src=x onerror=alert(1)> 를 넣어도 문자열 그대로 보인다.
   스크립트가 실행되면 안 된다
8. 키보드만으로 추가·수정·체크·삭제·필터를 전부 수행할 수 있다

## 5단계 — 되돌리기·백업·여러 탭과 마무리 (F9~F11)

```
D:\DSMP\study02_todolist 에서 작업한다.
docs/superpowers/specs/2026-10-01-할일관리앱-design.md 의 F9, F10, F11,
7.3(삭제 정책), 9.3 / 9.4, 10.4(수동 확인 목록)를 먼저 읽어라.
index.html 에는 1~4단계가 들어 있어 앱이 이미 동작한다.

남은 세 기능을 붙이고 마무리하라.

[F11 — 삭제 되돌리기]
삭제(F3)와 완료 항목 비우기(F7) 직후 목록 위에 띠를 띄운다:
  "'장보기' 을(를) 삭제했습니다.   [되돌리기]"
  "완료 항목 7개를 비웠습니다.     [되돌리기]"
- 8초 뒤 저절로 사라진다. 그 전에 다른 삭제가 일어나면 이전 되돌리기는 버린다.
  되돌릴 수 있는 것은 직전 삭제 한 번뿐이다
- 누르면 지워진 항목이 원래 번호 그대로 돌아온다. 번호를 새로 발급하지 않으므로
  정렬 위치도 원래 자리다. 다음번호 를 바꾸지 않는다
- 상태.마지막삭제 = {항목들, 설명, 시각}. 저장하지 않는다. 새로고침하면 사라지는
  것이 맞다 — 디스크까지 끌고 가면 "언제까지 되돌릴 수 있는가" 를 정의해야 한다
- 순수 함수 삭제되돌리기(상태) → 새 상태 를 1계층에 추가하고, 할일삭제 와
  완료항목비우기 가 마지막삭제 를 기록하도록 고친다
- 띠에 role="status"
- F7 의 confirm() 은 그대로 둔다. 일괄은 잃는 것이 커서 두 겹으로 막는다

[F10 — 백업 내보내기 / 가져오기]
바닥에 작고 흐린 링크 두 개: "백업 내려받기" / "백업 불러오기". 입력·체크 동선과
섞지 않는다(가져오기 오클릭은 덮어쓰기로 이어진다).
- 내보내기: 저장 형식과 같은 구조의 JSON 에 내보낸시각(UTC ISO) 한 필드만
  덧붙여 Blob 으로 내려 준다. 구조가 같아야 가져오기가 데이터검증을 재사용한다.
  파일명은 KST 기준: 할일백업-2026-10-01-1059.json.
  createObjectURL 뒤 revokeObjectURL 로 정리한다. 네트워크 요청 0건
- 가져오기: 숨긴 <input type="file" accept="application/json"> → FileReader →
  반드시 데이터검증을 통과시킨다. 백업 파일도 손으로 고쳐졌을 수 있다.
  내보낸시각은 무시한다
- 덮어쓰기다. 합치지 않는다(번호 충돌 해소와 중복 판정 규칙을 끌고 들어온다).
  confirm() 으로 확인하고, 확인 직후 현재 데이터를 할일앱.가져오기전백업 키에
  보존한 뒤 덮어쓴다
- 깨진 JSON 을 고르면 현재 데이터는 그대로 두고 경고만 띄운다
- 순수 함수 내보내기문자열만들기(상태, 지금), 백업파일이름(지금) 을 1계층에
  추가한다. 백업파일이름은 UTC 를 KST 로 환산한다
  (2026-10-01T15:30:00Z → 할일백업-2026-10-02-0030.json)

[F9 — 여러 탭]
window 의 storage 이벤트를 듣는다. 다른 탭이 할일앱.데이터 를 바꾸면 다시
불러와 그린다. 단, 편집 중(편집중번호 !== null)이면 편집이 끝날 때까지 반영을
미룬다 — 타이핑하는 중에 입력란이 날아가면 안 된다.

[검증 — 자가검증에 추가할 항목]
- 되돌리기: 삭제 → 되돌리기 → 원래 상태와 완전히 동일(번호·순서·완료 상태),
  일괄 비우기 → 되돌리기 → 전부 복귀, 두 번 연속 삭제하면 나중 것만,
  마지막삭제가 null 이면 상태 불변, 되돌린 뒤 마지막삭제는 null
- 백업 왕복: 내보내기문자열만들기 → JSON.parse → 데이터검증 결과가 원래 상태와
  동일. 빈 목록도 왕복. 내보낸시각이 있어도 데이터검증이 무시
- 백업파일이름의 KST 환산 2건(날짜 넘김 포함)

[마무리]
