# 할 일 관리 앱 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 하루 10~20개 규모의 할 일을 관리하는 단일 HTML 파일 앱을 만든다. 추가·수정·삭제·완료 체크·카테고리 분류·필터·진행률을 제공하고 localStorage로 영속한다.

**Architecture:** `index.html` 한 파일 안에 CONFIG → STORAGE → LOGIC → 파생 상태 → RENDER → EVENTS 6개 층을 주석으로 구획한다. LOGIC과 파생 상태 층은 DOM을 참조하지 않는 순수 함수이고, 상태 변경은 전부 `이벤트 → 상태 교체 → 저장 → 전체 재렌더` 한 방향으로 흐른다. 빌드 단계가 없어 Node 테스트 러너를 쓸 수 없으므로, 같은 파일 안에 인페이지 테스트 하네스를 두고 `?test` 쿼리로만 켠다.

**Tech Stack:** 순수 JavaScript (ES2020), HTML, CSS. 의존성 없음. 프레임워크·번들러·패키지 매니저 없음.

**Spec:** `PRD.md`

## Global Constraints

- 구현은 `index.html` **단일 파일**이다. HTML·CSS·JS를 전부 인라인한다. 추가 파일을 만들지 않는다.
- `file://`에서 더블클릭으로 동작해야 한다. ES 모듈(`type="module"`), `import`, `fetch`를 쓰지 않는다.
- 외부 의존성 0. CDN 링크, 폰트 로드, `package.json` 모두 금지.
- localStorage 키: `todolist.v1` / 손상 데이터 백업 키: `todolist.v1.corrupt`
- 카테고리는 3개 고정: `work`=업무 `#2563eb`, `personal`=개인 `#16a34a`, `study`=공부 `#9333ea`
- 할 일 텍스트: 정규화 후 1~200자. 입력란에 `maxlength="200"`.
- 화면 출력은 `textContent`만 쓴다. `innerHTML` 금지.
- ID 생성에 `crypto.randomUUID()`를 쓰지 않는다. `Date.now().toString(36) + "_" + Math.random().toString(36).slice(2, 7)`
- 상태 변경 시 전체 재렌더. 부분 DOM 갱신 금지.
- 목록 리스너는 `<ul>` 하나에만 붙인다 (이벤트 위임).
- 본문 최대 폭 600px, 가운데 정렬.
- 필터 선택은 저장하지 않는다. 새로고침 시 `status="active"`, `category="all"`로 돌아간다.
- 저장 상태 객체는 `{ version: 1, todos: [...] }` 형태를 유지한다.

## 검증 방법

Node 테스트 러너가 없다. 모든 "테스트 실행" 단계는 다음을 뜻한다.

1. 브라우저에서 `file:///D:/gamst/study02_todolist/index.html?test` 를 연다 (이미 열려 있으면 강제 새로고침)
2. 페이지 하단 테스트 패널의 **마지막 줄**을 읽는다
3. 형식: `TESTS: <통과수> passed, <실패수> failed`

에이전트로 실행할 경우 내장 브라우저의 `navigate` → `get_page_text`로 같은 줄을 읽는다.

## Review Focus

- **저장소에 유효 JSON이지만 스키마가 다른 값이 있을 때** (`todos`가 없거나 배열이 아님) — 파싱은 성공하므로 손상 처리를 통과해 렌더에서 터진다. 빈 목록으로 시작하고 원본을 백업해야 한다. → Task 2
- **저장소에 알 수 없는 `category` 값이 있을 때** (수동 편집, 구버전 데이터) — `CATEGORIES[cat]`이 `undefined`가 되어 배지 생성에서 터진다. 폴백 라벨로 그려야 한다. → Task 5
- **개행이나 연속 공백이 포함된 텍스트를 붙여넣을 때** — 한 줄 레이아웃이 깨진다. 공백을 정규화해야 한다. → Task 3
- **200자를 넘는 텍스트가 로직 층에 직접 들어올 때** — `maxlength`는 UI만 막는다. 로직에서도 거부해야 한다. → Task 3
- **같은 밀리초에 두 건을 연속 추가해 ID가 겹칠 때** — 수정·삭제가 엉뚱한 항목을 건드린다. 중복이면 다시 생성해야 한다. → Task 3

### Task 2: STORAGE 층

**Files:**
- Modify: `index.html` (STORAGE 구획 추가)

**Interfaces:**
- Consumes: `STORAGE_KEY`, `CORRUPT_KEY` (Task 1), 하네스 (Task 1)
- Produces:
  - `loadState(store)` → `{ state: { version: 1, todos: Todo[] }, error: null | "corrupt" | "unavailable" }`
  - `saveState(state, store)` → `{ ok: boolean, error: string | null }`
  - `store`는 `{ getItem, setItem, removeItem }`를 가진 객체. 기본값 `localStorage`. 테스트는 가짜 store를 넘긴다.

- [ ] **Step 1: 실패하는 테스트 작성**

```js
function fakeStore(initial) {
  const data = { ...initial };
  return {
    getItem: k => (k in data ? data[k] : null),
    setItem: (k, v) => { data[k] = String(v); },
    removeItem: k => { delete data[k]; },
    _data: data
  };
}

test("빈 저장소는 빈 목록을 돌려준다", () => {
  const r = loadState(fakeStore({}));
  assertDeep(r.state, { version: 1, todos: [] });
  assertEq(r.error, null);
});

test("저장한 상태를 그대로 다시 읽는다", () => {
  const s = fakeStore({});
  const state = { version: 1, todos: [{ id: "a", text: "x", category: "work", done: false, createdAt: 1, completedAt: null }] };
  assertEq(saveState(state, s).ok, true);
  assertDeep(loadState(s).state, state);
});

test("깨진 JSON은 빈 목록 + corrupt 백업", () => {
  const raw = "{{{깨짐";
  const s = fakeStore({ [STORAGE_KEY]: raw });
  const r = loadState(s);
  assertDeep(r.state.todos, []);
  assertEq(r.error, "corrupt");
  assertEq(s._data[CORRUPT_KEY], raw);
});

test("todos가 배열이 아니면 corrupt로 처리한다", () => {
  const raw = JSON.stringify({ version: 1, todos: "없음" });
  const s = fakeStore({ [STORAGE_KEY]: raw });
  const r = loadState(s);
  assertDeep(r.state.todos, []);
  assertEq(r.error, "corrupt");
  assertEq(s._data[CORRUPT_KEY], raw);
});

test("쓰기가 막히면 ok:false를 돌려준다", () => {
  const s = fakeStore({});
  s.setItem = () => { throw new Error("QuotaExceeded"); };
  assertEq(saveState({ version: 1, todos: [] }, s).ok, false);
});

test("저장소 자체가 없으면 unavailable", () => {
  const s = { getItem: () => { throw new Error("blocked"); }, setItem: () => {}, removeItem: () => {} };
  assertEq(loadState(s).error, "unavailable");
});
```

위 네 번째 테스트가 Review Focus의 "스키마가 다른 유효 JSON"을 덮는다.

- [ ] **Step 2: 테스트 실행 — 실패 확인**

Expected: `loadState is not defined`로 6건 실패, 마지막 줄 `TESTS: 1 passed, 6 failed`

- [ ] **Step 3: STORAGE 구획 구현**

`loadState(store = localStorage)`와 `saveState(state, store = localStorage)`를 CONFIG 아래에 추가한다.

`loadState`의 판정 순서: `getItem` 자체가 throw → `unavailable`. 값이 `null` → 빈 상태, `error: null`. 파싱 실패 **또는** `parsed.todos`가 배열이 아님 → 원본 문자열을 `CORRUPT_KEY`로 `setItem`한 뒤 빈 상태 + `corrupt`. 그 외 → `{ version: 1, todos: parsed.todos }`.

### Task 3: LOGIC 층

**Files:**
- Modify: `index.html` (LOGIC 구획 추가)

**Interfaces:**
- Consumes: `CATEGORIES`, `MAX_LEN` (Task 1)
- Produces: 모두 새 배열을 돌려주는 순수 함수. 거부되는 입력은 **원본 `todos`를 그대로** 돌려준다(참조 동일).
  - `normalizeText(text)` → `string` — 연속 공백(개행 포함)을 공백 하나로 바꾸고 `trim()`
  - `makeId(now = Date.now())` → `string`
  - `addTodo(todos, text, category, now = Date.now(), idFn = makeId)` → `Todo[]`
  - `toggleTodo(todos, id, now = Date.now())` → `Todo[]`
  - `editTodo(todos, id, text)` → `Todo[]`
  - `removeTodo(todos, id)` → `Todo[]`
  - `clearCompleted(todos, category = "all")` → `Todo[]`
  - `Todo` = `{ id, text, category, done, createdAt, completedAt }`

- [ ] **Step 1: 실패하는 테스트 작성**

`T()`는 이후 과제에서도 쓰는 공용 헬퍼이므로 테스트 구획 맨 위에 둔다.

```js
const T = (over = {}) => ({ id: "a", text: "x", category: "work", done: false, createdAt: 1, completedAt: null, ...over });

test("addTodo는 기본값을 채워 항목을 추가한다", () => {
  const r = addTodo([], "장 보기", "personal", 1000, () => "id1");
  assertEq(r.length, 1);
  assertDeep(r[0], { id: "id1", text: "장 보기", category: "personal", done: false, createdAt: 1000, completedAt: null });
});

test("공백만 입력하면 원본을 그대로 돌려준다", () => {
  const todos = [];
  assertEq(addTodo(todos, "   ", "work"), todos);
});

test("개행과 연속 공백을 공백 하나로 정규화한다", () => {
  const r = addTodo([], "앞\n뒤   사이", "work", 1, () => "id1");
  assertEq(r[0].text, "앞 뒤 사이");
});

test("정규화 후 200자를 넘으면 거부한다", () => {
  const todos = [];
  assertEq(addTodo(todos, "가".repeat(201), "work"), todos);
  assertEq(addTodo([], "가".repeat(200), "work", 1, () => "id1").length, 1);
});

test("생성한 ID가 이미 있으면 다시 생성한다", () => {
  let n = 0;
  const idFn = () => (n++ === 0 ? "dup" : "uniq");
  const r = addTodo([T({ id: "dup" })], "새 항목", "work", 1, idFn);
  assertEq(r[1].id, "uniq");
});

test("toggleTodo는 done을 뒤집고 completedAt을 설정한다", () => {
  const r = toggleTodo([T()], "a", 500);
  assertEq(r[0].done, true);
  assertEq(r[0].completedAt, 500);
  const back = toggleTodo(r, "a", 900);
  assertEq(back[0].done, false);
  assertEq(back[0].completedAt, null);
});

test("editTodo는 텍스트를 바꾸고 빈 텍스트는 거부한다", () => {
  assertEq(editTodo([T()], "a", "  새 제목 ")[0].text, "새 제목");
  const todos = [T()];
  assertEq(editTodo(todos, "a", "   "), todos);
});

test("removeTodo는 해당 id만 지운다", () => {
  const r = removeTodo([T({ id: "a" }), T({ id: "b" })], "a");
  assertEq(r.length, 1);
  assertEq(r[0].id, "b");
});

test("clearCompleted는 완료 항목만, 카테고리 범위 안에서 지운다", () => {
  const todos = [
    T({ id: "1", done: true, category: "work" }),
    T({ id: "2", done: true, category: "study" }),
    T({ id: "3", done: false, category: "work" })
  ];
  assertDeep(clearCompleted(todos, "all").map(t => t.id), ["3"]);
  assertDeep(clearCompleted(todos, "work").map(t => t.id), ["2", "3"]);
});

test("없는 id를 건드리면 원본을 그대로 돌려준다", () => {
  const todos = [T()];
  assertEq(toggleTodo(todos, "없음"), todos);
  assertEq(removeTodo(todos, "없음"), todos);
});
```

### Task 4: 파생 상태 — 가시 목록과 진행률

**Files:**
- Modify: `index.html` (파생 상태 구획 추가)

**Interfaces:**
- Consumes: `Todo` 형태와 `T()` 헬퍼 (Task 3)
- Produces:
  - `visibleTodos(todos, statusFilter, categoryFilter)` → `Todo[]` — `statusFilter`는 `"active" | "all" | "done"`, `categoryFilter`는 `"all"` 또는 카테고리 키
  - `progress(todos, category = "all")` → `{ done: number, total: number, percent: number }` — `percent`는 0~100 정수(반올림), `total`이 0이면 0

- [ ] **Step 1: 실패하는 테스트 작성**

```js
test("미완료는 추가순, 완료는 최근 완료순으로 정렬한다", () => {
  const todos = [
    T({ id: "b", createdAt: 20 }),
    T({ id: "a", createdAt: 10 }),
    T({ id: "c", done: true, completedAt: 100 }),
    T({ id: "d", done: true, completedAt: 200 })
  ];
  assertDeep(visibleTodos(todos, "active", "all").map(t => t.id), ["a", "b"]);
  assertDeep(visibleTodos(todos, "done", "all").map(t => t.id), ["d", "c"]);
  assertDeep(visibleTodos(todos, "all", "all").map(t => t.id), ["a", "b", "d", "c"]);
});

test("원본 배열을 변형하지 않는다", () => {
  const todos = [T({ id: "b", createdAt: 20 }), T({ id: "a", createdAt: 10 })];
  visibleTodos(todos, "all", "all");
  assertEq(todos[0].id, "b");
});

test("카테고리 필터는 상태 필터와 AND로 결합한다", () => {
  const todos = [T({ id: "a", category: "work" }), T({ id: "b", category: "study" })];
  assertDeep(visibleTodos(todos, "active", "work").map(t => t.id), ["a"]);
  assertDeep(visibleTodos(todos, "done", "work").map(t => t.id), []);
});

test("progress는 완료 비율을 정수 퍼센트로 돌려준다", () => {
  const todos = [T({ id: "a", done: true }), T({ id: "b" }), T({ id: "c" })];
  assertDeep(progress(todos), { done: 1, total: 3, percent: 33 });
});

test("할 일이 없으면 0/0 0%", () => {
  assertDeep(progress([]), { done: 0, total: 0, percent: 0 });
  assertDeep(progress([T({ category: "work" })], "study"), { done: 0, total: 0, percent: 0 });
```
