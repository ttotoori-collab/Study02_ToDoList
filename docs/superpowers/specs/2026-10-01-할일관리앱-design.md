# 할 일 관리 앱 — 제품 요구사항 정의서 (PRD)

작성일: 2026-10-01 (KST)
상태: 검토 대기

---

## 1. 배경과 목적

하루 10-20개의 할 일을 관리하는 **개인용** 앱이다. 학습 과제가 아니라 매일 실제로
쓸 도구다. 학습(순수 JS·DOM·localStorage 숙달)은 부수적 효과로 따라오되,
설계가 충돌할 때는 **실사용 편의를 우선한다**.

기존 할 일 앱을 쓰지 않는 이유는 이 PRD의 관심사가 아니다. 다만 그 선택이
설계에 주는 함의는 분명하다 — 이 앱은 **설치도 가입도 없이, 파일 하나로
끝나야 한다**. 그 단순함이 이 앱의 존재 이유다.

### 1.1 성공 기준

측정 가능한 형태로만 적는다.

| 번호 | 기준 | 확인 방법 |
|---|---|---|
| S1 | 할 일 하나를 추가하는 데 마우스가 필요하지 않다 | 제목 타이핑 → `Enter` 한 번으로 목록에 들어간다 |
| S2 | 새로고침·브라우저 재시작·기기 재부팅 후 데이터가 100% 남아 있다 | 각 경우를 수동으로 1회씩 확인 |
| S3 | 저장이 실패하면 사용자가 **반드시** 그 사실을 안다 | 조용한 실패 0건. 저장 불가 상황에서 경고 띠가 보인다 |
| S4 | 순수 로직이 전부 자가검증을 통과한다 | `index.html?검증` 으로 열어 전항목 통과 |
| S5 | 설치 단계가 0이다 | 파일을 열면 바로 쓸 수 있다 (11.1 의 단서 참고) |

### 1.2 실패 조건

하나라도 해당하면 이 앱은 실패다.

- 데이터가 사용자 모르게 사라진다
- 화면에 보이는 것과 저장된 것이 어긋난다
- 할 일 하나 적는 데 여러 번 클릭해야 한다

## 2. 사용자와 사용 맥락

사용자는 한 명 — 이 앱을 만든 본인이다. 그래서 다음이 전부 범위 밖이다:
계정, 권한, 공유, 협업, 다중 사용자.

| 항목 | 내용 |
|---|---|
| 사용 빈도 | 하루 여러 번. 아침에 목록을 적고, 종일 체크하고, 중간중간 추가 |
| 한 번에 보는 양 | 미완료 10-20개. 완료 항목을 비우기 전까지 누적 |
| 기기 | 주로 데스크톱 브라우저. 휴대폰에서도 열릴 것 (같은 기기 아니면 데이터는 공유되지 않음) |
| 수명 | 누적 목록. 날짜로 끊지 않는다 |

## 3. 합의된 결정

브레인스토밍에서 확정된 사항이다. 구현 중 이 표를 뒤집으려면 먼저 PRD를 고친다.

| 항목 | 결정 | 이유 |
|---|---|---|
| 목록 수명 | **누적 목록** — 날짜 개념 없음 | 날짜 전환·이월 로직이 없어 버그 표면이 가장 작다 |
| 완료 항목 처리 | 목록 아래로 내려 흐리게 표시, **"완료 항목 비우기"** 버튼으로 사용자가 직접 정리 | 체크한 보람을 눈으로 확인하고, 정리 시점은 사람이 정한다 |
| 구현 형태 | **단일 HTML 파일** (`index.html`) — HTML·CSS·JS 한 파일 | 빌드·의존성·모듈 로딩 문제가 전부 사라진다 |
| 렌더 전략 | **상태 하나 + 변경 시 목록 전체 다시 그리기** (접근법 A) | "화면과 데이터가 어긋나는" 버그가 구조적으로 생기지 않는다 |
| 저장소 | `localStorage`, 평소 쓰는 키는 `할일앱.데이터` 하나 | 서버 없음. 동기 API 라 흐름이 단순하다 |
| 백업 | **JSON 파일 내보내기/가져오기 포함** (F10) | `localStorage` 는 사용 기록 삭제·브라우저 교체·기기 이동을 견디지 못한다 |
| 삭제 보호 | **되돌리기 8초** (F11). 개별 삭제에 확인 창을 두지 않는다 | 확인 창은 마찰이 있으면서도 익숙해지면 무의식적으로 눌러 보호가 안 된다 |
| 진행률 자리 | **헤더 안**, 레이블에 현재 필터 이름 | 맨 위에서 스크롤 없이 보인다. 필터와 멀어지는 만큼 이름으로 보완한다 |
| 외부 의존성 | **없음** — 라이브러리·CDN·폰트·아이콘 전부 0 | 오프라인 동작, 네트워크 요청 0건 |
| 카테고리 | 업무 / 개인 / 공부 **고정 3개** | 요청 그대로. 사용자 정의 카테고리는 범위 밖 |
| 진행률 기준 | **지금 보고 있는 목록** 기준 | 카테고리를 걸러 보면 그 카테고리의 비율이 궁금한 것이 자연스럽다 |
| 식별자 규약 | **한글 식별자·한글 주석** | study01_MNIST 저장소 규약 유지 |
| 시각 처리 | 저장은 UTC ISO 8601, 표시는 KST 환산 | 전역 CLAUDE.md 규약 |
| 검증 방식 | `index.html?검증` 으로 순수 함수 자가검증 | 파일 하나를 유지하면서 저장·계산 로직의 침묵 파손을 막는다 |

## 4. 범위

### 4.1 포함 (v1)

- 할 일 추가 (제목 + 카테고리)
- 할 일 수정 (제목 + 카테고리, 제자리 편집)
- 할 일 삭제 (개별)
- 완료 체크 / 체크 해제
- 카테고리 필터 (전체 / 업무 / 개인 / 공부)
- 진행률 표시 (막대 + 숫자)
- 완료 항목 일괄 비우기
- localStorage 자동 저장 / 불러오기
- 저장 실패·데이터 손상 시 사용자 통보와 원본 보존
- 백업 내보내기 / 가져오기 (JSON 파일)
- 삭제 되돌리기 (직전 한 건, 8초)
- 여러 탭 동시 사용 시 다른 탭 변경 반영
- 다크 모드 (`prefers-color-scheme`)
- `?검증` 자가검증

### 4.2 제외 (YAGNI)

요청에 없고, 없어도 S1-S5 를 달성한다. 넣지 않는 이유를 함께 적는다.

| 제외 항목 | 이유 |
|---|---|
| 로그인·계정·서버·기기 간 동기화 | 사용자 한 명, 기기 하나. 서버가 생기는 순간 "설치 0단계"가 깨진다 |
| 마감일·알림·반복 할 일 | 날짜 개념을 안 쓰기로 한 결정과 직접 충돌 |
| 우선순위·태그·하위 작업 | 10-20개 규모에서 카테고리 3개면 충분하다 |
| 검색 | 10-20개는 눈으로 찾는 것이 빠르다 |
| 드래그로 순서 바꾸기 | 정렬 규칙이 고정이라 수동 순서를 둘 자리가 없다 |
| 통계·그래프·연속 기록 | 진행률 하나로 족하다 |
| 영구 되돌리기 이력 | 직전 한 건·8초만 되돌린다 (F11). 그 이상은 삭제 이력 저장과 용량 관리를 끌고 들어온다 |
| 수정·완료 체크 되돌리기 | 되돌리기는 **삭제 전용** 이다. 수정은 다시 고치면 되고, 체크는 다시 누르면 된다 |

`localStorage` 는 새로고침은 견디지만 브라우저 사용 기록 삭제·브라우저 교체·기기
이동은 견디지 못한다. 그래서 **백업 내보내기/가져오기는 제외하지 않고 F10 으로
포함한다** (2026-10-01 결정).

## 5. 데이터 모델

### 5.1 저장 형식

평소에 읽고 쓰는 키는 하나다: **`할일앱.데이터`**

나머지 두 개는 **사고가 났을 때만 생기는 보존용** 이다. 앱이 읽는 일은 없고,
사용자가 개발자 도구로 꺼내 쓰기 위한 것이다.

| 키 | 언제 생기는가 | 누가 읽는가 |
|---|---|---|
| `할일앱.데이터` | 항상 | 앱 (F8) |
| `할일앱.손상된데이터.<UTC ISO 시각>` | 저장 데이터가 손상돼 일부를 버릴 때 (7.2) | 사람만 |
| `할일앱.가져오기전백업` | 백업 가져오기로 덮어쓰기 직전 (F10) | 사람만 |

```json
{
  "스키마버전": 1,
  "다음번호": 43,
  "할일목록": [
    {
      "번호": 42,
      "제목": "PRD 검토하기",
      "카테고리": "업무",
      "완료": false,
      "만든시각": "2026-10-01T01:59:12.345Z"
    },
    {
      "번호": 41,
      "제목": "이벤트 위임 정리",
      "카테고리": "공부",
      "완료": true,
      "만든시각": "2026-10-01T01:40:03.002Z"
    }
  ]
}
```

| 필드 | 형 | 설명 |
|---|---|---|
| `스키마버전` | 정수 | 현재 `1`. 형식이 바뀌면 올리고 이전 버전 변환기를 둔다 |
| `다음번호` | 정수 | 다음에 발급할 `번호`. 삭제해도 재사용하지 않는다 |
| `번호` | 정수 | 항목의 영구 식별자. 정렬 기준이기도 하다 |
| `제목` | 문자열 | 1-200자. 앞뒤 공백은 저장 전에 제거 |
| `카테고리` | 문자열 | `"업무"` / `"개인"` / `"공부"` 중 하나 |
| `완료` | 불 | 완료 여부 |
| `만든시각` | 문자열 | UTC ISO 8601 (`...Z`). v1 화면에는 표시하지 않는다 |

`만든시각` 은 v1 에서 쓰이지 않는데도 저장한다. 나중에 되돌려 채울 수 없는
유일한 정보라서다. 표시는 하지 않으므로 화면 복잡도는 늘지 않는다.

`완료시각` 은 두지 않는다. 완료 항목의 정렬도 `번호` 내림차순이라 필요가 없고,
완료 항목은 비우면 사라진다.

### 5.2 메모리 상태

화면 상태는 저장하지 않는다. 새로고침하면 필터가 "전체"로 돌아오는 것이
오히려 자연스럽다.

```js
상태 = {
  할일목록: [],        // 저장됨
  다음번호: 1,         // 저장됨
  선택카테고리: "전체",  // 저장 안 함
  편집중번호: null,     // 저장 안 함 — 제자리 편집 중인 항목
  저장가능: true,       // 저장 안 함 — localStorage 사용 가능 여부
  다른탭변경대기: false, // 저장 안 함 — 편집 중에 들어온 다른 탭 변경 (F9)
  마지막삭제: null,     // 저장 안 함 — {항목들, 설명, 시각}. 되돌리기용 (F11)
}
```

`마지막삭제` 를 저장하지 않는 것은 의도다. 새로고침하면 되돌리기가 사라지는 쪽이
맞다 — 디스크까지 끌고 가면 "언제까지 되돌릴 수 있는가"를 정의해야 한다 (7.3).

`저장하기()` 는 `스키마버전`, `다음번호`, `할일목록` 만 직렬화한다.

`선택카테고리` 는 상태에 두지만 **입력 줄의 카테고리 선택값은 상태에 두지 않는다.**
입력 줄은 다시 그리지 않으므로(8.2) `<select>` 가 마지막 선택을 그대로 들고 있다.
상태로 올리면 복원 코드만 늘고 얻는 것이 없다.

### 5.3 불변식

구현이 항상 지켜야 하는 성질이다. 자가검증이 이것들을 확인한다.

1. `할일목록` 안의 `번호` 는 유일하다
2. 모든 `번호` 는 `다음번호` 보다 작다
3. 모든 `카테고리` 는 고정 3개 중 하나다
4. 모든 `제목` 은 공백을 제거한 뒤 길이가 1-200 이다
5. 화면에 보이는 것은 언제나 현재 `상태` 를 그린 결과다 (중간 상태가 없다)

## 6. 기능 요구사항

각 항목에 수용 기준을 붙인다. 구현 완료 판정은 이 기준으로 한다.

### F1. 할 일 추가

입력 줄은 **제목 입력란 + 카테고리 선택 + 추가 버튼** 으로 이루어진다.

- 제목 입력란에서 `Enter` 를 누르면 추가된다 (S1)
- 카테고리 선택의 기본값은 **마지막으로 추가할 때 고른 카테고리** 를 유지한다.
  같은 종류의 할 일을 연달아 적는 일이 흔하다
- 추가 후 입력란은 비워지고 **포커스가 그대로 입력란에 남는다**. 연속 입력이 끊기지 않아야 한다
- 새 항목은 `번호 = 다음번호` 를 받고 `다음번호` 가 1 증가한다
- 추가된 항목은 미완료 묶음의 **맨 위** 에 나타난다

**수용 기준**
- 제목이 비었거나 공백만이면 추가되지 않고, 입력란 아래에 "할 일을 입력해 주세요"가 보이며 포커스는 입력란에 남는다
- 앞뒤 공백은 제거되어 저장된다 (`"  빨래  "` → `"빨래"`)
- 200자를 넘는 입력은 입력 자체가 막힌다 (`maxlength`)
- 같은 제목을 두 번 추가할 수 있다. 중복은 정상이다

### F2. 할 일 수정

항목의 **제목을 누르거나 연필 버튼을 누르면** 그 자리에서 편집 상태가 된다.
`상태.편집중번호` 에 해당 번호가 들어간다.

- 편집 상태에서는 제목이 입력란으로, 카테고리가 선택 상자로 바뀐다
- `Enter` 또는 포커스 이탈로 **확정**, `Escape` 로 **취소**
- 한 번에 한 항목만 편집한다. 다른 항목 편집을 시작하면 앞의 것은 확정된다

**수용 기준**
- 편집 중 다시 그려져도 포커스와 커서 위치가 유지된다 (7.5)
- 제목을 비우고 확정하면 수정이 거부되고 편집 상태가 유지된다. 항목이 삭제되지는 **않는다**.
  이때 빠져나오는 길은 `Escape` 다 — 비운 채로는 확정할 수 없으니 취소만이 출구다
- `Escape` 로 취소하면 원래 제목·카테고리가 그대로다
- 카테고리를 바꾸면 현재 필터에서 벗어날 수 있다. 그때 항목이 목록에서 사라지는 것은 정상이며, 필터 개수와 진행률이 즉시 갱신된다

### F3. 할 일 삭제

각 항목의 `✕` 버튼으로 **즉시** 삭제한다. 확인 대화상자는 없다.
대신 **되돌리기** 를 띄운다 (F11).

확인 창을 두지 않는 이유는 두 가지다. 하루 여러 번 하는 동작에 클릭을 하나 더
붙이면 쓸모가 떨어지고, 더 중요하게는 **확인 창은 익숙해지면 무의식적으로
눌러서 실제로는 아무것도 막지 못한다.** 되돌리기는 마찰이 0 이면서 실수를
실제로 복구한다.

**수용 기준**
- 삭제된 `번호` 는 다시 발급되지 않는다
- 삭제 직후 필터 개수와 진행률이 갱신된다
- 편집 중인 항목을 삭제하면 `편집중번호` 가 `null` 로 돌아간다
- 삭제 직후 되돌리기 띠가 뜬다 (F11)

### F4. 완료 체크

각 항목 왼쪽의 체크박스로 완료를 뒤집는다.

- 완료된 항목은 **완료 묶음** 으로 이동해 흐리게, 제목에 취소선이 붙는다
- 체크 해제하면 미완료 묶음으로 돌아온다
- 항목 줄 전체를 클릭 영역으로 쓰지 않는다. 체크박스와 제목(편집)의 역할이 겹치면 오조작이 난다

**수용 기준**
- 체크하면 그 항목이 완료 묶음으로 내려가고 진행률이 즉시 오른다
- 체크박스는 실제 `<input type="checkbox">` 라서 `Space` 로 조작된다
- 완료 항목도 수정·삭제할 수 있다

### F5. 카테고리 필터

`[전체 18] [업무 7] [개인 6] [공부 5]` 네 개의 버튼. 각 버튼에 **그 카테고리의
전체 개수** (완료 포함)를 함께 보인다.

**수용 기준**
- 선택된 버튼은 시각적으로 구분된다 (`aria-pressed="true"`)
- 필터를 바꾸면 목록과 진행률이 함께 바뀐다
- 개수가 0인 카테고리 버튼도 사라지지 않는다. 자리가 움직이면 오클릭이 난다
- 필터는 저장되지 않는다. 새로고침하면 "전체"다

### F6. 진행률

막대 하나와 숫자 하나. **지금 보고 있는 목록** 기준이다.
자리는 **헤더 안** — 화면 맨 위에서 스크롤 없이 보인다.

```
할 일                          ███████████░░░░░░░░  전체 7 / 18 (39%)
```

레이블 앞에 **현재 필터 이름** 을 붙인다 (`전체` / `업무` / `개인` / `공부`).
막대가 헤더로 올라가면서 필터 버튼과 멀어지는데, 이름이 없으면 "무엇의 39%인지"가
흐려진다. 업무 필터를 켜면 `업무 7 / 12 (58%)` 로 바뀐다.

백분율 규칙 — 반올림이 신뢰를 깎지 않도록 양 끝을 막는다.

```js
function 진행률계산(목록) {
  const 전체수 = 목록.length;
  const 완료수 = 목록.filter(할일 => 할일.완료).length;

  let 백분율;
  if (전체수 === 0)            백분율 = 0;
  else if (완료수 === 0)       백분율 = 0;
  else if (완료수 === 전체수)  백분율 = 100;
  // 다 끝내지 않았는데 100% 로 보이면 안 되고,
  // 하나라도 끝냈는데 0% 로 보이면 안 된다.
  else 백분율 = Math.min(99, Math.max(1, Math.round((완료수 / 전체수) * 100)));

  return { 완료수, 전체수, 백분율 };
}
```

**수용 기준**
- 항목이 0개면 `0 / 0 (0%)` 과 함께 "할 일이 없습니다"가 보이고 막대는 비어 있다
- 200개 중 199개 완료는 **99%** 로 보인다 (반올림은 100 이지만 깎는다). 100% 는 전부 완료일 때만이다
- 300개 중 1개 완료는 **1%** 로 보인다 (반올림은 0 이지만 올린다). 0% 는 하나도 완료하지 않았을 때만이다
- 막대에 `role="progressbar"` 와 `aria-valuenow` / `aria-valuemin` / `aria-valuemax` 가 붙는다
- 필터를 바꾸면 레이블의 필터 이름도 함께 바뀐다

### F7. 완료 항목 비우기

바닥의 `완료 항목 비우기 (7)` 버튼. 괄호 안은 **현재 필터 기준** 완료 개수다.

- 누르면 `confirm()` 으로 한 번 확인한다. 여러 건이 한 번에 사라지는
  유일한 동작이라 개별 삭제(F3)와 달리 확인을 둔다
- 확인 뒤에도 **되돌리기** 를 띄운다 (F11). 확인과 되돌리기는 배타가 아니다 —
  일괄 삭제는 잃는 것이 크므로 두 겹으로 막는다
- **현재 필터에 보이는 완료 항목만** 지운다. 업무 필터에서 눌렀는데 공부 할 일이
  사라지면 안 된다
- 완료 항목이 0개면 버튼은 비활성 상태다

**수용 기준**
- 업무 필터에서 비우면 업무의 완료 항목만 사라지고 다른 카테고리는 그대로다
- 확인 대화상자에서 취소하면 아무것도 지워지지 않는다
- 비운 뒤 `다음번호` 는 줄어들지 않는다
- 비운 직후 되돌리기 띠가 뜨고, 누르면 지운 항목이 **전부** 돌아온다 (F11)

### F8. 저장과 불러오기

- 상태가 바뀌는 **모든** 경로에서 즉시 저장한다. 별도 저장 버튼은 없다
- 앱을 열면 `할일앱.데이터` 를 읽어 검증한 뒤 시작한다
- 키가 없으면 빈 목록으로 시작한다 (첫 실행)

**수용 기준**
- 할 일을 추가하고 새로고침하면 그대로 있다 (S2)
- 모든 변경(추가·수정·삭제·체크·비우기) 후 새로고침해도 결과가 유지된다
- 저장이 실패하면 7.1 / 7.2 의 통보가 보인다

### F9. 여러 탭 동시 사용

같은 앱을 탭 두 개에 열어 두는 일은 흔하다. 한쪽 변경이 다른 쪽에 묻히면
데이터가 사라진 것으로 보인다.

- `window` 의 `storage` 이벤트를 듣는다
- 다른 탭이 `할일앱.데이터` 를 바꾸면 **다시 불러와 그린다**
- 편집 중(`편집중번호 !== null`)이면 편집이 끝날 때까지 반영을 미룬다.
  타이핑하는 중에 입력란이 날아가면 안 된다

**수용 기준**
- 탭 A 에서 추가하면 탭 B 에 자동으로 나타난다
- 탭 B 에서 편집 중이면 그 편집 내용이 날아가지 않는다

### F10. 백업 내보내기 / 가져오기

`localStorage` 하나에만 데이터가 있으면 브라우저 설정 조작 한 번으로 전부
사라진다. 7.2 가 손상 데이터를 보존해도 저장소 자체가 비워지면 보존할 원본조차
없다. 그 구멍을 막는 유일한 기능이다.

바닥에 작은 링크 두 개를 둔다: `백업 내려받기` / `백업 불러오기`.
눈에 띄는 버튼이 아니다. 자주 쓰는 기능이 아니므로 입력·체크 동선을 방해하면 안 된다.

**내보내기**

- 현재 저장 데이터와 **같은 구조** 의 JSON 을 파일로 내려 준다. 거기에 `내보낸시각`
  (UTC ISO) 한 필드만 덧붙인다. 구조가 같아야 가져오기가 `데이터검증` 을 그대로 쓴다
- 파일명은 **KST 기준** 이다: `할일백업-2026-10-01-1059.json` (전역 규약 — 파일
  이름의 날짜는 KST)
- `Blob` + `URL.createObjectURL` 로 만들고, 내려받은 뒤 `revokeObjectURL` 로 정리한다
- 네트워크 요청이 없다. 파일은 브라우저 안에서 만들어진다

**가져오기**

- 숨긴 `<input type="file" accept="application/json">` 으로 파일을 고른다
- `FileReader` 로 읽어 **7.2 의 `데이터검증` 을 그대로 통과시킨다.** 백업 파일도
  손으로 고쳐졌을 수 있으므로 신뢰하지 않는다. `내보낸시각` 은 무시한다
- **덮어쓰기** 다. 현재 목록과 합치지 않는다 — 합치려면 번호 충돌 해소와 중복 판정
  규칙이 필요하고, 그 복잡도는 이 앱이 감당할 이유가 없다
- 덮어쓰기 전에 `confirm()` 으로 확인하고, **확인 직후 현재 데이터를
  `할일앱.가져오기전백업` 키에 보존한다.** 7.2 와 같은 원칙이다 — 되돌릴 수 없는
  일에 원본 없이 들어가지 않는다
- `다음번호` 는 가져온 데이터와 현재 데이터의 **최대 번호 + 1** 로 맞춘다.
  덮어쓴 뒤에도 번호가 겹치지 않는다

**수용 기준**
- 내려받은 파일을 그대로 가져오면 목록이 **완전히 동일** 하다 (왕복 무손실)
- 깨진 JSON 을 고르면 현재 데이터는 **그대로 남고** 경고 띠만 뜬다
- `스키마버전` 이 2인 파일을 고르면 가져오기를 거부한다 (7.2 와 같은 규칙)
- 가져오기 후 `할일앱.가져오기전백업` 키에 이전 데이터가 있다
- 가져오기 후 할 일을 추가해도 번호가 겹치지 않는다
- 내려받기·불러오기 모두 네트워크 요청을 만들지 않는다

### F11. 삭제 되돌리기

삭제(F3)와 완료 항목 비우기(F7) 직후, 목록 위에 띠가 뜬다.

```
'장보기' 을(를) 삭제했습니다.                    [ 되돌리기 ]
완료 항목 7개를 비웠습니다.                       [ 되돌리기 ]
```

- **8초** 뒤 저절로 사라진다. 그 전에 다른 삭제가 일어나면 이전 되돌리기는 버려진다.
  되돌릴 수 있는 것은 **직전 삭제 한 번** 뿐이다
- 누르면 지워진 항목이 **원래 번호 그대로** 돌아온다. 번호를 새로 발급하지 않으므로
  정렬 위치도 원래 자리다
- 되돌린 뒤 띠는 사라진다
- 띠에 `role="status"` 를 둔다. 스크린 리더가 삭제 사실을 읽는다

**왜 확인 창이 아닌가.** 확인 창은 마찰이 있으면서도 보호가 약하다 — 매번 뜨면
사용자는 내용을 읽지 않고 누르는 습관을 들이고, 그 순간부터 아무것도 막지 못한다.
되돌리기는 정상 동작을 전혀 늦추지 않으면서 실수한 **그 건** 을 실제로 복구한다.

**상태와 수명.** `상태.마지막삭제` 에 `{항목들, 설명, 시각}` 을 담는다.
저장하지 않는다 — 새로고침하면 사라지는 것이 맞다. 되돌리기를 디스크까지
끌고 가면 "언제까지 되돌릴 수 있는가"라는 질문이 생기고, 그 답을 정의하는 순간
복잡도가 설계 전체로 번진다.

**수용 기준**
- 삭제 → 되돌리기 → 목록이 삭제 전과 **완전히 같다** (번호·순서·완료 상태 포함)
- 일괄 비우기 → 되돌리기 → 지운 항목이 전부 돌아온다
- 두 번 연속 삭제하면 **나중 것만** 되돌릴 수 있다
- 8초가 지나면 띠가 사라지고 되돌릴 수 없다
- 되돌리기는 `다음번호` 를 바꾸지 않는다
- 새로고침하면 되돌리기는 사라진다 (저장하지 않는다)

## 7. 오류 처리와 경계 조건

실사용 도구에서 가장 중요한 절이다. S3("조용한 실패 0건")이 여기서 지켜진다.

### 7.1 localStorage 를 쓸 수 없다

사생활 보호 모드, 브라우저 설정, `file://` 제약 등으로 막힐 수 있다.

- 시작 시 쓰기 시험으로 가용성을 확인하고 `상태.저장가능` 에 기록한다
- 모든 `localStorage` 접근은 `try` / `catch` 로 감싼다. 던지는 예외가 앱을 멈추게 해서는 안 된다
- 쓸 수 없으면 화면 맨 위에 **사라지지 않는 경고 띠** 를 띄운다:

  > ⚠ 이 브라우저에서는 저장할 수 없습니다. 새로고침하면 작성한 내용이 사라집니다.

- 앱은 메모리에서 정상 동작한다. 못 쓰게 막지는 않는다

### 7.2 저장된 데이터가 손상되었다

JSON 파싱 실패, 형이 다름, 필드 누락, 손으로 고친 흔적 등.

`데이터검증(임의값)` 이 **살릴 수 있는 것만 살려** `{상태, 복구실패수}` 를 돌려준다.
`복구실패수` 는 버려진 항목의 개수다 — 고쳐서 살린 항목은 세지 않는다.

이 함수는 **두 입구에서 함께 쓰인다**: `localStorage` 에서 불러올 때(F8)와 백업
파일을 가져올 때(F10). 백업 파일도 손으로 고쳐졌을 수 있으므로 같은 의심을 받는다.

| 상황 | 처리 |
|---|---|
| JSON 파싱 실패 | 빈 목록으로 시작 |
| 최상위가 객체가 아님 | 빈 목록으로 시작 |
| `할일목록` 이 배열이 아님 | 빈 목록으로 시작 |
| 개별 항목이 객체가 아님 | 그 항목만 버린다 |
| `제목` 이 없거나 공백만 | 그 항목만 버린다 (제목 없는 할 일은 의미가 없다) |
| `제목` 이 200자 초과 | 200자로 자른다 |
| `카테고리` 가 고정 3개에 없음 | `"개인"` 으로 교정한다 (버리면 항목에 닿을 수 없다) |
| `완료` 가 불이 아님 | `Boolean()` 으로 변환 |
| `번호` 가 없거나 중복 | 새 번호를 발급한다 |
| `만든시각` 이 없거나 형식 오류 | 현재 시각으로 채운다 |
| `다음번호` 가 최대 `번호` 보다 작거나 없음 | `최대 번호 + 1` 로 교정 |
| `스키마버전` 이 1보다 큼 | 빈 목록으로 시작 (미래 형식을 해석할 수 없다) |

**무엇 하나라도 버리거나 고쳤다면:**

1. **원본 문자열을 `할일앱.손상된데이터.<UTC ISO 시각>` 키에 그대로 보존한다.**
   조용히 날리는 것은 이 앱의 실패 조건이다
2. 경고 띠로 알린다:

   > ⚠ 저장된 데이터 일부를 읽을 수 없어 3개 항목을 복구하지 못했습니다.
   > 원본은 `할일앱.손상된데이터.2026-10-01T02:00:00.000Z` 에 보관했습니다.

### 7.3 삭제 정책

| 동작 | 사전 확인 | 사후 되돌리기 | 이유 |
|---|---|---|---|
| 개별 삭제 (F3) | 없음 | **8초** (F11) | 하루 여러 번 하는 동작이라 마찰을 두지 않는다. 실수는 되돌리기로 복구한다 |
| 완료 항목 비우기 (F7) | `confirm()` | **8초** (F11) | 여러 건이 한 번에 사라지므로 두 겹으로 막는다 |
| 백업 가져오기 덮어쓰기 (F10) | `confirm()` | `할일앱.가져오기전백업` 키 | 목록 전체가 바뀌므로 디스크에 원본을 남긴다 |

**8초가 지나면 복구할 수 없다.** 되돌리기는 메모리에만 있고 저장하지 않는다.
이 경계를 넘긴 손실에 대한 안전망은 백업(F10)이다.

되돌리기를 영구 이력으로 만들지 않는 이유: "언제까지 되돌릴 수 있는가"를
정의하는 순간 삭제 이력 저장, 용량 관리, 이력 UI 가 줄줄이 따라온다.
직전 한 건·8초로 끊으면 실수의 99% 를 잡으면서 복잡도는 상태 필드 하나로 끝난다.

### 7.4 저장 용량 초과

`QuotaExceededError` 가 날 수 있다. 5MB 면 수만 개 분량이라 현실적으로 닿지
않지만, 닿았을 때 조용히 실패해서는 안 된다.

- 경고 띠: "저장 공간이 꽉 찼습니다. 완료 항목을 비워 주세요."
- 메모리 상태는 유지한다. 사용자가 비우면 다시 저장이 된다

### 7.5 다시 그린 뒤 포커스를 잃는다

접근법 A 에서 유일하게 주의할 지점이다(설계 토론에서 언급한 그대로).

`렌더()` 끝에서:

- `편집중번호` 가 있으면 그 항목의 제목 입력란에 포커스를 되돌리고,
  선택 영역(`selectionStart` / `selectionEnd`)까지 복원한다
- 입력 줄은 다시 그리지 않으므로(8.2) 복원할 것이 없다. 포커스가 그대로 살아 있다

즉 복원해야 하는 대상은 **제자리 편집 중인 입력란 하나뿐** 이고, 복원 코드는
`렌더()` 의 끝 한 군데에만 있어야 한다. 흩어지면 접근법 A 의 이점이 사라진다.

### 7.6 입력값 안전

혼자 쓰는 앱이라도 규칙으로 못 박는다.

- **사용자 입력은 `textContent` 로만 넣는다.** 제목을 `innerHTML` 에 넣는 코드는
  리뷰에서 거부한다
- 구조를 만드는 `innerHTML` 에는 사용자 문자열이 섞이지 않는다
- 이유: 백업을 붙여 넣거나 다른 기기에서 데이터를 옮기는 순간, "내 입력"이라는
  가정이 깨진다

### 7.7 그 밖의 경계

| 경계 | 처리 |
|---|---|
| 항목 0개 | "할 일이 없습니다" 안내. 입력 줄과 필터는 그대로 보인다 |
| 필터 결과만 0개 | "업무 할 일이 없습니다" |
| 완료 항목만 있고 미완료 0개 | 미완료 묶음 자리에 "모두 끝냈습니다" |
| 매우 긴 제목 | `overflow-wrap: anywhere` 로 줄바꿈. 레이아웃을 깨지 않는다 |
| 항목 1,000개 | 렌더 16ms 이내 (8.5) |

### 8.3 핵심 불변식 — `적용()` 이 유일한 통로

접근법 A 의 전부가 이 함수에 들어 있다.

```js
// 상태를 바꾸는 유일한 경로. 다른 곳에서 상태를 직접 수정하지 않는다.
function 적용(새상태) {
  상태 = 새상태;   // 1. 교체
  저장하기(상태);  // 2. 저장
  렌더();          // 3. 그리기
}
```

**규칙**
- 1계층 순수 함수는 **새 상태를 만들어 돌려주기만** 한다. 저장도 렌더도 하지 않는다
- 사건 핸들러는 순수 함수를 불러 새 상태를 얻고, `적용()` 에 넘긴다
- `상태` 를 직접 대입하는 곳은 `적용()` 과 최초 초기화, 단 두 곳뿐이다

이 규칙이 지켜지면 "저장은 했는데 화면이 안 바뀜" / "화면은 바뀌었는데 저장이 안 됨"이
구조적으로 불가능하다.

### 8.4 데이터 흐름

```
사용자 입력
    │
    ▼
사건 핸들러 (4계층)
    │  ├ 입력값을 다듬는다 (공백 제거 등)
    │  └ 유효하지 않으면 여기서 멈추고 안내만 띄운다
    ▼
순수 함수 (1계층)  —  현재 상태 + 입력 → 새 상태
    │
    ▼
적용()  ──▶ 저장하기() (2계층) ──▶ localStorage
    │                                   │ 실패하면
    │                                   └▶ 상태.저장가능 = false
    ▼
렌더() (3계층)
    │  ├ 목록걸러내기 → 목록정렬 → 목록그리기
    │  ├ 진행률계산 → 진행률그리기 (헤더, 레이블에 필터 이름)
    │  ├ 카테고리별개수 → 필터그리기
    │  ├ 마지막삭제 → 되돌리기띠그리기 (F11)
    │  └ 포커스 복원 (7.5)
    ▼
화면
```

**렌더는 상태만 읽는다.** 렌더 안에서 상태를 바꾸지 않는다 — 무한 루프의 씨앗이다.

### 8.5 성능

항목 1,000개에서 렌더 16ms 이내를 목표로 한다. 수단:

- 목록은 `DocumentFragment` 에 조립한 뒤 **한 번** 교체한다. 항목마다 DOM 에 붙이면 리플로가 반복된다
- 이벤트 리스너는 `<ul>` **한 개** 에만 붙인다 (이벤트 위임). 항목마다 붙이면 항목 수에 비례해 늘어난다
- 어느 버튼을 눌렸는지는 항목의 `data-번호` 와 `data-동작` 으로 판별한다

하루 10-20개면 한참 뒤에도 수백 개 수준이다. 이 수단들로 충분하고, 가상 스크롤 같은
것은 넣지 않는다.

### 9.2 시각 규칙

- 카테고리는 **색 점 + 글자** 로 표시한다. 색만으로 구분하면 색각 이상에서 읽을 수 없다
- 카테고리 색: 업무·개인·공부 각각 하나. CSS 변수로 모아 둔다
- 완료 항목: 투명도를 낮추고 제목에 취소선. 색만 바꾸지 않는다
- 완료 묶음 앞에 구분선과 `완료 N` 라벨
- 다크 모드는 `prefers-color-scheme: dark` 에서 CSS 변수만 재정의한다

### 9.3 반응형

- 360px 폭(휴대폰)부터 가로 스크롤 없이 동작한다
- 좁은 화면에서 입력 줄은 두 줄로 내려간다 (제목 / 카테고리+버튼)
- 터치 대상은 최소 44×44px. 연필과 ✕ 가 붙어 있으면 잘못 누른다

### 9.4 접근성

- 체크박스는 실제 `<input type="checkbox">`, 버튼은 실제 `<button>`
- 진행률 막대에 `role="progressbar"` + `aria-valuenow` / `aria-valuemin` / `aria-valuemax`
- 필터 버튼에 `aria-pressed`
- 아이콘만 있는 버튼(`✎`, `✕`)에 `aria-label` — "수정", "삭제"
- 경고 띠에 `role="alert"`
- **키보드만으로 전부 조작할 수 있다**: `Tab` 이동, `Space` 체크, `Enter` 확정, `Escape` 취소
- 포커스 표시를 지우지 않는다 (`outline: none` 금지)

## 10. 검증 전략

### 10.1 왜 자가검증인가

단일 HTML 파일에는 테스트 프레임워크를 둘 자리가 없다. 그런데 **저장·불러오기·
데이터검증이 조용히 깨지면 데이터가 사라진다** — 이 앱의 실패 조건이다.
사람이 매번 수동으로 확인할 수 있는 종류의 로직도 아니다.

그래서 1계층(순수 함수)만을 대상으로 하는 자가검증을 파일 안에 둔다.

### 10.2 동작 방식

- `index.html?검증` 으로 열면 앱 화면 대신 **검증 결과** 를 보여 준다
- 평소(`index.html`)에는 검증 코드가 **실행되지 않는다**. 화면에 흔적도 없다
- 1계층만 시험한다. DOM 과 localStorage 는 건드리지 않으므로 실제 데이터가 안전하다
- 결과는 `통과 N / 실패 M` 과 실패 항목의 기대값·실제값을 함께 띄운다

### 10.3 검증 항목

**순수 변환**
- `할일추가` — 번호 발급, `다음번호` 증가, 맨 위 배치, 공백 제거
- `할일추가` — 빈 제목·공백만이면 상태가 바뀌지 않는다
- `할일수정` — 제목·카테고리 변경, 다른 항목 불변, 없는 번호는 무시
- `할일삭제` — 해당 항목만 사라지고 `다음번호` 는 줄지 않는다
- `완료뒤집기` — 두 번 뒤집으면 원래대로
- `완료항목비우기` — 지정 카테고리의 완료 항목만 사라진다. 다른 카테고리와 미완료는 그대로

**조회·계산**
- `목록정렬` — 미완료가 먼저, 각 묶음 안에서 번호 내림차순
- `목록걸러내기` — `"전체"` 는 전부, 카테고리는 해당만
- `카테고리별개수` — 완료 포함 개수
- `진행률계산` — 경계 전부:
  - `0/0` → 0%
  - `0/10` → 0%
  - `10/10` → 100%
  - `199/200` → **99%** — 반올림은 100 이지만 깎는다
  - `1/300` → **1%** — 반올림은 0 이지만 올린다
  - `1/3` → 33%

**데이터검증 — 7.2 표의 모든 행**
- JSON 깨짐 / 최상위가 배열·문자열·null / `할일목록` 이 배열 아님
- 항목이 객체 아님 / 제목 없음 / 제목 공백만 / 제목 201자
- 카테고리 미지정·오타 → `"개인"` 교정
- `완료` 가 문자열 `"true"` → 불 변환
- 번호 중복 / 번호 없음 → 재발급 후 유일성
- `다음번호` 가 최대 번호보다 작음 → 교정
- `스키마버전` 이 2 → 빈 목록
- 정상 데이터는 **아무것도 바꾸지 않는다** (가장 중요한 항목)

**삭제 되돌리기 (F11)**
- `할일삭제` → `삭제되돌리기` → **원래 상태와 완전히 동일** (번호·순서·완료 상태)
- `완료항목비우기` → `삭제되돌리기` → 지운 항목이 전부 돌아온다
- 두 번 연속 삭제 → `삭제되돌리기` 는 **나중 것만** 되돌린다
- `마지막삭제` 가 `null` 일 때 `삭제되돌리기` 는 상태를 바꾸지 않는다
- 되돌리기가 `다음번호` 를 바꾸지 않는다
- 되돌린 뒤 `마지막삭제` 가 `null` 이 된다 (두 번 되돌리기 불가)

**백업 왕복 (F10)**
- `내보내기문자열만들기` → `JSON.parse` → `데이터검증` 으로 **원래 상태와 동일** 해진다
  (왕복 무손실. 이 항목이 통과하지 않으면 백업은 백업이 아니다)
- `내보낸시각` 필드가 있어도 `데이터검증` 이 무시한다
- 빈 목록도 왕복한다
- `백업파일이름` — UTC `2026-10-01T01:59:12Z` 를 넣으면 KST 로 환산된
  `할일백업-2026-10-01-1059.json` 이 나온다
- `백업파일이름` — UTC 가 전날 15:00 이후면 KST 는 다음 날이다
  (`2026-10-01T15:30:00Z` → `할일백업-2026-10-02-0030.json`)

**불변식 (5.3)**
- 위 모든 변환 뒤에 1-4 번 불변식이 유지된다

### 10.4 수동 확인 목록

자가검증이 닿지 않는 것(DOM·브라우저·저장소·파일)은 손으로 확인한다.
README 에 체크리스트로 남긴다.

11번은 F10 을 범위에 넣으면서 함께 들어왔다. 파일을 내려받고 다시 읽는 경로는
브라우저가 하는 일이라 자가검증이 닿지 않는데, 이 경로가 조용히 깨지면 백업을
가진 줄 알고 안심한 채 데이터를 잃는다.

1. 추가 → 새로고침 → 남아 있다 (S2)
2. 수정·삭제·체크·비우기 각각 후 새로고침 → 결과 유지
3. 입력란에서 `Enter` 만으로 추가된다. 포커스가 입력란에 남는다 (S1)
4. 편집 중 다른 탭에서 변경 → 편집 내용이 날아가지 않는다 (F9)
5. 탭 두 개 → 한쪽 추가 → 다른 쪽에 나타난다 (F9)
6. 사생활 보호 모드에서 열기 → 경고 띠가 보이고 앱은 동작한다 (7.1)
7. 개발자 도구로 `할일앱.데이터` 를 망가뜨리고 새로고침 → 경고 띠 + `할일앱.손상된데이터.*` 키 생성 (7.2)
8. 키보드만으로 추가·수정·체크·삭제·필터 전부 수행 (9.4)
9. 360px 폭에서 가로 스크롤이 없다 (9.3)
10. 다크 모드 전환 시 글자가 읽힌다 (9.2)
11. **백업 왕복** — 내려받기 → 할 일을 몇 개 지우기 → 불러오기 → 목록이 되돌아온다.
    `할일앱.가져오기전백업` 키가 생겼다. 깨진 JSON 을 고르면 현재 데이터가 그대로다 (F10)
12. **되돌리기** — 삭제 → 띠가 뜬다 → 되돌리기 → 원래 자리로 돌아온다.
    8초를 기다리면 띠가 사라진다. 되돌린 뒤 새로고침해도 항목이 남아 있다 (F11)

### 11.1 실행 방법에 관한 단서

`file://` 로 열면 브라우저에 따라 `localStorage` 가 막힌다. Chrome 은 대체로
동작하지만 Safari 는 제한적이다. 이것이 "브라우저에서 바로 실행"과 부딪히는
유일한 지점이다.

- 막히면 7.1 의 경고 띠가 반드시 뜬다. **사용자가 모르고 쓰는 일은 없다**
- README 의 1순위 권장은 **로컬 서버** 또는 **GitHub Pages** 다.
  두 경우 모두 `localStorage` 가 정상 동작한다
- `file://` 더블클릭도 지원하되, 경고 띠가 뜨면 위 방법으로 안내한다

```bash
python -m http.server 8000
```

## 12. 구현 순서 제안

자세한 작업 분해는 다음 단계(구현 계획)에서 한다. 큰 덩어리만 적는다.

1. **골격** — `index.html` 정적 HTML + CSS 변수 + 다크 모드
2. **1계층** — 순수 함수 전부. 동시에 5계층 자가검증을 쓴다
3. **2계층** — 저장·불러오기·손상 데이터 보존. 7.1 / 7.2 / 7.4
4. **3계층** — 렌더. 목록·진행률·필터·바닥
5. **4계층** — 사건. `적용()`, 이벤트 위임, F1 / F3 / F4 / F5 / F7
6. **되돌리기** — F11. 1계층에 `삭제되돌리기` 와 `마지막삭제` 기록이 이미 있으므로
   띠와 8초 타이머만 붙인다
7. **제자리 편집** — F2 와 포커스 복원(7.5). 가장 까다로운 부분이라 뒤로 둔다
8. **백업** — F10. `데이터검증` 을 재사용하므로 2번 뒤라면 언제든 붙일 수 있다
9. **여러 탭** — F9
10. **다듬기** — 반응형(9.3), 접근성(9.4), 수동 확인 목록(10.4)

2번과 7번이 이 앱에서 틀리기 쉬운 두 곳이다.
