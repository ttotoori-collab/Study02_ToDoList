# Study02_ToDoList

브라우저에서 바로 실행되는 개인용 할 일 관리 앱이다. 하루 10~20개 수준의 할 일을 적어 두고, 카테고리로 나눠 보면서 완료 여부와 진행률을 확인한다.

서버도 계정도 빌드 도구도 없다. HTML 파일 하나를 브라우저로 열면 실행되고, 데이터는 브라우저의 localStorage에 남는다.

## 현재 상태

**v1 구현 완료.** `index.html` 하나로 동작한다.

- [PRD.md](PRD.md) — 요구사항, 데이터 모델, 화면 설계, 완료 기준
- [PROMPTS.md](PROMPTS.md) — PRD를 클로드 코드에서 실행할 5단계 프롬프트로 나눈 것
- [구현 계획](docs/superpowers/plans/2026-10-01-todolist.md) — 7개 과제와 각 과제의 테스트

## 실행 방법

`index.html`을 브라우저로 열기만 하면 된다. 설치할 것도, 띄울 서버도 없다.

테스트는 주소 끝에 `?test`를 붙여서 연다.

```
index.html?test
```

페이지 아래에 테스트 결과가 줄마다 나오고, 마지막 줄에 `TESTS: 33 passed, 0 failed`가 찍힌다. 평소에 쓸 때는 붙이지 않으면 된다.

## 기능

- 할 일 추가, 수정, 삭제
- 완료 체크
- 카테고리 분류 (업무, 개인, 공부)
- 필터 — 완료 상태(미완료 / 전체 / 완료)와 카테고리를 함께 적용한다
- 진행률 보기 — 전체 진행률 하나와 카테고리별 진행률을 함께 보여준다
- 완료한 할 일 일괄 비우기
- 새로고침해도 유지되는 저장

할 일은 날짜로 묶지 않는다. 하나의 목록에 계속 쌓이고, 완료한 항목도 지우기 전까지 남는다.

몇 가지 동작은 써 보기 전에는 눈에 띄지 않는다.

- 입력란은 Enter로 추가되고, 추가 후에도 포커스와 카테고리 선택이 그대로 남는다. 10~20개를 연달아 적어 넣는 흐름에 맞췄다.
- 수정은 그 줄에서 바로 한다. Enter로 저장, Esc로 취소한다.
- 삭제와 완료 비우기는 확인 창을 한 번 거친다. 되돌리기가 없기 때문이다.
- 저장이 실패하면 화면 위에 경고가 뜬다. 저장된 줄 알고 브라우저를 닫는 일을 막기 위해서다.

## 기술 스택

- HTML, CSS, 순수 자바스크립트
- 라이브러리와 프레임워크 없음
- 파일 구성: `index.html` 하나 (CSS와 자바스크립트를 같은 파일 안에 둔다)

## 구조

`index.html` 안쪽은 여섯 구획으로 나뉜다. 위에서 아래로 의존한다.

| 구획 | 하는 일 |
|---|---|
| CONFIG | 카테고리 정의, 저장 키, 길이 제한 |
| STORAGE | localStorage 읽기와 쓰기, 손상 데이터 보존 |
| LOGIC | 추가·수정·삭제·완료·일괄정리 (DOM을 모르는 순수 함수) |
| 파생 상태 | 보여줄 목록 계산과 진행률 집계 (역시 순수 함수) |
| RENDER | 상태를 화면에 반영 |
| EVENTS | 상태 보유와 리스너 연결 |

상태가 바뀌면 목록 전체를 다시 그린다. 바뀐 줄만 골라 갱신하지 않는다. 항목이 수백 개여도 체감상 즉시이고, "상태는 바뀌었는데 화면이 안 따라오는" 종류의 버그가 아예 생기지 않는다.

LOGIC과 파생 상태는 DOM을 참조하지 않는다. `?test`로 켜는 테스트가 겨냥하는 곳이 이 두 구획이다.
