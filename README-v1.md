# Study02_ToDoList

하루 10~20개 규모의 할 일을 관리하는 개인용 웹 앱. 브라우저에서 단독으로 동작하고,
새로고침·재시작 후에도 데이터가 유지된다.

## 현재 상태

**설계 단계 — 구현 전.** 이 저장소에는 아직 PRD(설계 문서)만 있다.

→ [PRD: 할 일 관리 앱 설계 문서](PRD.md)

## 주요 기능

- 할 일 추가 / 수정(인라인) / 삭제
- 완료 체크
- 카테고리 3종 — 업무 · 개인 · 공부
- 필터 — 완료 상태(미완료/전체/완료) × 카테고리, AND 결합
- 진행률 — 전체 바 하나 + 카테고리별 요약
- 완료 항목 일괄 비우기

## 기술 선택

| 항목 | 선택 |
|---|---|
| 구현 | **단일 HTML 파일** (`index.html`) — HTML·CSS·JS 전부 인라인 |
| 실행 | 파일 더블클릭 (`file://`). 로컬 서버 불필요 |
| 저장 | `localStorage` 키 `todolist.v1` |
| 의존성 | 없음. 프레임워크·번들러·빌드 단계 없음 |

단일 파일을 택한 대가로 Node 단위 테스트가 불가능하다. 대신 URL에 `?test`를 붙이면
순수 로직(추가/수정/삭제/토글/진행률 집계)을 검사하는 인페이지 테스트 패널이 열린다.
자세한 근거는 PRD 2장과 7장에 있다.

## 범위 밖

날짜 필드가 없는 **하나의 누적 목록**이다. "오늘의 할 일" 같은 날짜 단위 묶음,
어제 미완료 항목의 이월, 기간 기반 자동 정리는 모두 없다.

그 밖에 제외한 것: 마감일, 사용자 조작 정렬, 로그인/계정, 서버·다중 기기 동기화,
반복 할 일, 알림, 우선순위, 하위 작업, 태그, 검색, 되돌리기(undo),
카테고리 추가/삭제, 다크 모드 토글, 데이터 내보내기/가져오기.
